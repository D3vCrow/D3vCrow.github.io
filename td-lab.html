Five Champions, One Architecture

The five classes share one turret backbone: a state machine that picks targets, fires projectiles, and serves a per-class action UI. Four named systems hold it together.

01

NodeBehavior Turret State Machine

Each turret runs a finite state machine: Idle, Tracking, Firing, Cooldown. The five champion classes (Archer, Fire / Ice / Poison wizards, Warrior) plug into the same skeleton with their own projectile prefabs, fire rates, and FX, so adding a class is data + a child override, not a rewrite.

02

WaveSpawner + Waypoints

Waves are authored as ordered enemy lists with delays. WaveSpawner drives the loop, enemies follow a Waypoints path with index-based progression instead of NavMesh, predictable, debuggable, and fast for the size of the lanes.

03

UnitBuilder Placement

Click a build node, pick a class, the UnitBuilder validates funds, spawns the prefab, and binds it to the node. Placement raycasts and budget checks live in one component instead of being smeared across UI, economy, and turret spawn code.

04

OverlapSphere Lock-On + Lerp Tracking

Targets are queried via Physics.OverlapSphere on a layer mask, the closest valid enemy is chosen, and the turret rotates toward it via Quaternion.Lerp for smooth tracking. Projectiles inherit the lock so shots feel committed, not snapped, while the FSM stays simple.

Highlight

First Grown-Up Systems

Fantasy Tower Defence is the first project where I stopped writing one-off scripts and started thinking in systems: a state machine that doesn't care which class drives it, a spawner that doesn't care which path it walks, a builder that doesn't care which prefab it places. That mindset is the one I still ship with.
