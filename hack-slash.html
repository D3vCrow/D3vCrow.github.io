Systems

Combat Input as Expression

Most action games turn input into a button press. Hack and Slash turns it into a gesture, a pose, a lookpoint. Four named systems carry that intent.

01

Radial-Drag Combo Selector

Mouse-drag on the Y-axis snaps to up / center / down. Each direction queues an attack (Queue<int>), a coroutine performs the combo, and the cooldown ring fills as input is spent. DOTween animates the cursor; threshold detection lives in AttackSelectorUI.cs.

02

Camera-Pitch Aim Offset

A MultiAimConstraint on the rig points where the camera looks. The data offset is interpolated by cameraTransform.eulerAngles.x clamped to ±maxOffset in AimControl.cs. Clean Lerp-based aim, no gimbal stitching.

03

Timeline + Signal Boss Phases

Boss fights scripted in Unity Timeline. Phase transitions fire via Signal ScriptableObjects (ActivateControlsSignal, DeactivateControlsSignal, EnterPhase2). Cinematics and gameplay control swap on the same playable, no narrative bool flags.

04

Architecture

Generic Singleton<T> for shared state, custom RPGInputActions via the Unity Input System, and a curated middleware stack (JohnStairs RCC, Blaze AI, AYellowpaper SerializedCollections, Magic Light Probes, KriptoFX VolumetricBloodFX) for the parts that don't deserve to be reinvented.

Highlight

Newest On Disk

Hack and Slash is the most recent of my Unity projects, the only one running on Unity 6.2. It exists to prove I'm still actively building, not just maintaining old work. The radial-drag selector started as a question, what if the attack is the input motion, and it stuck because it felt better than buttons did.
