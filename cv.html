Approach

How I Work

Unity is hands-on — I write the C#, own the systems, debug the edge cases. For web, Python tooling, localization pipelines and research — I direct AI. My job there is the part AI still can't do: architecture, intent, and taste. That means writing the spec, choosing the boundaries, reading every diff, and refusing outputs that look right but aren't.

Step 01

Architect

Define the data flow, module boundaries, and failure modes before a single prompt is written. 7 years of Unity architecture transfers here — I know what a well-scoped system looks like.

Step 02

Specify

Write the prompt as a spec, not a wish. Success criteria, constraints, existing patterns to respect. Output quality is bounded by input quality — so the input is the real work.

Step 03

Review

Read the diff. Run the code. Question any abstraction I didn't ask for. If I can't explain what was built and why, I don't ship it — even if it passes tests.

Step 04

Iterate

Fix edge cases, trim gold-plating, tighten the spec where the AI guessed wrong. Keep going until the result is the one I would have written if I had the time. The AI is the tool. I own the result.
